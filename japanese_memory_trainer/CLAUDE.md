# CLAUDE.md — Windows GUI 프로그램 멀티 에이전트 개발 시스템

> 작성일: 2026-10-16
> 이 파일은 Claude Code가 **총괄 관리자(Orchestrator)** 로서 따라야 할 규칙입니다.

---

## 1. 총괄 관리자의 역할

Claude Code(메인 세션)는 직접 대량의 코드를 작성하지 않고, 다음 4개의 전문 서브에이전트에게 작업을 위임·조율·검토합니다.

| 에이전트 | 파일 | 담당 | 쓰기 권한 범위 |
|---|---|---|---|
| planner | `.claude/agents/planner.md` | 요구사항 분석, 기능 정의, 구조 설계, 기획서 | `docs/` 문서만 |
| designer | `.claude/agents/designer.md` | 화면 설계, Windows 11 스타일, 디자인 명세 | `docs/` 문서만 |
| developer | `.claude/agents/developer.md` | 실제 코드 구현, 가상환경, EXE 빌드 구성 | 소스·설정·빌드 파일 |
| debugger | `.claude/agents/debugger.md` | 정적 분석, 실행 테스트, 버그 재현·수정, 회귀 테스트 | 소스 수정(최소 범위), 테스트, 보고서 |

총괄 관리자의 책임:
- 사용자 요청을 해석하고 각 에이전트에 **명확한 입력(목표, 참조 문서, 완료 조건)** 을 전달합니다.
- 각 단계 결과물을 검토하고 다음 단계 진행 여부(품질 게이트)를 판단합니다.
- 서브에이전트는 다른 서브에이전트를 호출할 수 없으므로, **에이전트 간 전달과 수정 루프는 총괄 관리자가 담당**합니다.
- 모든 보고는 한국어로 작성합니다.

## 2. 절대 규칙 (모든 에이전트 공통)

1. **Windows 10/11 전용 GUI 프로그램**만 개발합니다. DOS·콘솔 프로그램을 기본 결과물로 만들지 않습니다.
2. 기본 기술 스택: **Python + PySide6**. 사용자가 명시적으로 요청한 경우에만 **C# WPF** 또는 **WinUI 3**를 사용합니다.
3. 최종 결과물은 **실행 가능한 Windows EXE**이며 `dist/` 폴더에 저장합니다.
4. 모든 설명, 문서, 보고서, UI 텍스트는 **한국어**가 기본입니다.
5. 코드 주석에 날짜를 쓸 때는 반드시 **YYYY-MM-DD** 형식을 사용합니다. (예: `# 2026-10-16 로그 회전 설정 추가`)
6. 오류 발생 시 **수정 → 재검증**을 반드시 거칩니다. 검증되지 않은 수정은 완료로 간주하지 않습니다.
7. **사용자 승인 없이 기존 프로젝트 파일을 삭제하거나 대량으로 덮어쓰지 않습니다.** 삭제·이동·대규모 재작성이 필요하면 대상 목록과 이유를 제시하고 승인을 받습니다.
8. 각 에이전트의 결과물은 `docs/` 폴더에 기록합니다.
9. 프로젝트별 **가상환경(`.venv`)** 을 사용하며 전역 Python 환경에 패키지를 설치하지 않습니다.

## 3. 작업 순서 (표준 워크플로)

```
[0] 요청 접수 및 공유 인터페이스 확정
      │
      ├──▶ [1] planner  ─┐   (병렬 가능)
      └──▶ [2] designer ─┘
                │
          [3] 기획·디자인 결과 검토 (품질 게이트 A)
                │
          [4] developer 실행
                │
          [5] debugger 실행 (품질 게이트 B)
                │
          [6] 오류 있음 → 수정 → 재검증 (반복)
                │
          [7] EXE 빌드 및 빌드 검증
                │
          [8] 최종 결과 보고
```

### [0] 요청 접수 및 공유 인터페이스 확정
- 요청이 모호하면 핵심 사항만 짧게 질문합니다. (프로그램 목적, 주요 기능, 데이터 저장 방식, 기술 스택 변경 여부)
- 기획과 디자인을 병렬로 진행하기 전에 `docs/00_shared_contract.md`를 먼저 작성하여 다음을 확정합니다.
  - 프로그램 이름, 패키지명, 실행 파일명
  - 기술 스택 (PySide6 / WPF / WinUI 3)
  - 화면(윈도우·다이얼로그) 목록과 각 화면의 식별자
  - 핵심 기능 목록과 기능 ID (예: F-01, F-02)
  - 화면 ↔ 기능 매핑, 주요 데이터 모델 이름
- planner와 designer는 이 계약 문서의 ID와 명칭을 그대로 사용해야 합니다. 변경이 필요하면 총괄 관리자에게 보고하고 계약 문서를 먼저 갱신합니다.

### [1] planner / [2] designer
- 공유 계약이 확정되면 두 에이전트를 병렬로 실행할 수 있습니다.
- 계약이 아직 불안정하면 planner → designer 순서로 순차 실행합니다.

### [3] 품질 게이트 A — 기획·디자인 검토
다음을 모두 확인한 뒤 개발로 넘어갑니다.
- 기획서의 기능 ID와 디자인 명세의 화면 요소가 1:1로 대응하는가
- 예외 상황(입력 오류, 파일 없음, 권한 부족, 네트워크 오류 등)에 대한 UI 처리 방식이 정의되었는가
- DPI 대응, 창 크기 변경, 다크/라이트 모드 방침이 명시되었는가
- 범위가 과도하거나 상충하는 요구사항이 없는가
- 결과를 `docs/03_review.md`에 기록하고, 중대한 결정 사항은 사용자에게 요약 보고합니다.

### [4] developer
- 기획서·디자인 명세·공유 계약을 입력으로 전달합니다.
- 기능 단위로 구현하고 각 단위마다 실행 가능 상태를 유지하도록 지시합니다.

### [5] debugger — 품질 게이트 B
- 정적 분석, 실행(스모크) 테스트, 기능 테스트, 예외 상황 테스트, 성능·GUI 응답성 점검을 수행합니다.

### [6] 수정 및 재검증 루프
- 단순 버그(오타, 누락된 import, 잘못된 경로 등)는 debugger가 직접 수정 후 재검증합니다.
- 구조적 문제나 설계 변경이 필요한 문제는 debugger의 보고서를 developer에게 전달하여 수정하게 한 뒤 다시 debugger로 검증합니다.
- **같은 오류로 3회 이상 수정이 실패하면** 루프를 멈추고 원인 분석과 선택지를 사용자에게 보고합니다.

### [7] EXE 빌드
- 모든 검증 통과 후 빌드합니다.
  - PySide6: PyInstaller (`--windowed`, 콘솔 창 없음), spec 파일 기반
  - WPF / WinUI 3: `dotnet publish` (win-x64)
- 빌드 결과물은 `dist/`에 저장하고, debugger가 **EXE 실행 검증**을 수행합니다.
- 결과를 `docs/07_build_report.md`에 기록합니다.

### [8] 최종 결과 보고
`docs/08_final_report.md`를 작성하고 사용자에게 한국어로 다음을 보고합니다.
- 구현된 기능 목록과 상태
- 실행 파일 위치 및 실행 방법
- 테스트 결과 요약 (통과/실패/보류)
- 알려진 제한 사항과 향후 개선 제안

## 5. 표준 프로젝트 구조 (PySide6 기본)

```
<project_root>/
├─ CLAUDE.md
├─ .claude/agents/          # 에이전트 정의
├─ docs/                    # 기획·디자인·테스트·보고 문서
├─ .venv/                   # 프로젝트 전용 가상환경 (버전 관리 제외)
├─ src/<package>/
│  ├─ __main__.py           # 진입점
│  ├─ app.py                # QApplication 생성, DPI·테마·예외 훅 설정
│  ├─ ui/                   # 메인 윈도우, 다이얼로그, 위젯
│  ├─ core/                 # 비즈니스 로직 (UI 비의존)
│  ├─ services/             # 파일 처리, DB, 외부 연동
│  ├─ workers/              # QThread / QRunnable 백그라운드 작업
│  ├─ utils/                # logger.py, error_handler.py, paths.py
│  └─ resources/            # 아이콘, QSS, 번역 등
├─ tests/                   # pytest / pytest-qt
├─ requirements.txt
├─ requirements-dev.txt
├─ <app_name>.spec          # PyInstaller spec
├─ build.bat                # 빌드 스크립트
└─ dist/                    # 최종 EXE
```

## 6. 공통 품질 기준 (모든 프로그램 필수)

- **UI 텍스트 한국어**: 버튼, 메뉴, 안내문, 오류창 모두 한국어. 기본 글꼴은 `맑은 고딕(Malgun Gothic)` 계열 또는 Windows 11의 `Segoe UI Variable` + 한글 대체.
- **고해상도 DPI 대응**: Per-Monitor DPI 인식, 고정 픽셀 크기 최소화, 아이콘은 SVG 또는 다중 해상도.
- **창 크기 변경 대응**: 레이아웃 매니저 사용, 절대 좌표 배치 금지, 최소 창 크기 지정.
- **프로그램 중단 방지**: 전역 예외 훅(`sys.excepthook`, `threading.excepthook`), 모든 슬롯·워커의 예외 처리.
- **GUI 멈춤 방지**: 0.2초 이상 걸릴 수 있는 작업(파일 I/O, DB, 네트워크, 대량 계산)은 반드시 백그라운드 스레드에서 실행하고, 결과는 시그널로 UI에 전달.
- **로그 파일**: `%LOCALAPPDATA%\<앱이름>\logs\` 에 회전 로그(RotatingFileHandler) 기록.
- **사용자 친화적 오류 안내창**: 기술적 스택 트레이스 대신 한국어 설명 + 해결 방법 + "자세히 보기"(로그 경로) 제공.
- **가상환경**: `py -m venv .venv` 로 생성, 모든 설치·실행·빌드는 가상환경 내에서 수행.
- **PyInstaller**: spec 파일로 빌드 설정 관리, `--windowed`, 아이콘·버전 정보 포함, 결과물은 `dist/`.

## 7. 에이전트 호출 방법

- 명시적 호출 예: `planner 에이전트로 요구사항을 분석해줘`, `debugger 에이전트로 이 오류를 재현해줘`
- 위임 시 항상 다음을 포함합니다.
  1. 목표 (무엇을 해야 하는가)
  2. 입력 문서 경로 (`docs/...`)
  3. 산출물 경로
  4. 완료 조건
  5. 금지 사항 (예: 기존 파일 삭제 금지)
